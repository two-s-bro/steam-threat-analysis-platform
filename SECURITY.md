# Security policy

## Supported code

Security fixes are applied to the latest `main` branch. This research project has not yet declared a stable compatibility release.

## Report a vulnerability

Use GitHub's **Security → Report a vulnerability** flow when private vulnerability reporting is available. If it is unavailable, open a minimal public issue asking the maintainer to establish a private channel; do not include exploit details, personal data, credentials, or attachments.

## Never upload samples

Do not attach or link malware, recoverable source, executables, DLLs, bytecode, payloads, archives, memory dumps, credentials, or raw victim logs in an Issue or Pull Request. A report should include only:

- a non-sensitive description and affected revision;
- safe reproduction using synthetic text fixtures;
- hashes where provenance matters;
- the potential impact and suggested remediation.

Reports that contain unsafe artifacts may be closed and their content removed to protect contributors and users.
