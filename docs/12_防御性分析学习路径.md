# 防御性分析学习路径

本路径面向检测工程、事件响应和安全数据工程。练习只使用仓库中的合成/脱敏文本，不需要也不允许取得或运行原始恶意文件。

## 共同安全规则

- 不执行、编译、解包、反编译、解密或恢复任何样本；
- 不访问历史 C2，不把去武器化 IOC 改回可访问地址；
- 不读取真实用户的 Steam 配置，也不复刻钓鱼界面；
- 不向 Issue、PR、在线沙箱或第三方服务上传样本与原始日志；
- 发现疑似受害者标识时，先脱敏再记录结论。

## 阶段一：理解证据与数据边界

1. 阅读 [`RESEARCH_PROVENANCE.md`](RESEARCH_PROVENANCE.md) 和 [`SAMPLE_HANDLING.md`](SAMPLE_HANDLING.md)。
2. 区分“直接观察”“静态推断”和“未验证假设”。
3. 用 `evidence/sample-hashes.json` 验证哈希清单的字段与格式，不获取对应二进制。
4. 运行 `python scripts/verify_public_safety.py`，理解公开树门禁。

## 阶段二：从脱敏样例建立攻击时间线

1. 使用 `backend/src/main/resources/samples/` 中的小型文本夹具。
2. 将事件映射到 dropper、persistence、injection、phishing、heartbeat 等调查阶段。
3. 标注证据来源和置信度，避免把时间相关性误写成因果关系。
4. 为解析器补充仅含合成标识的单元测试。

## 阶段三：编写检测规则

1. 从文件名组合、Run 键名称、配置篡改和去武器化域名中提取稳定信号。
2. 避免使用受害者唯一标识作为规则条件。
3. 为每条规则记录误报来源、适用数据源和失效条件。
4. 用无害文本做正例和反例；规则未命中不等于文件安全。

## 阶段四：事件响应与恢复验证

1. 根据 [`how-to-remove.md`](how-to-remove.md) 设计只读检查清单。
2. 记录持久化项、文件完整性和代理/DNS 历史证据。
3. 将账号保护、会话撤销、系统重装或恢复决策交由受影响用户和组织流程确认。
4. 复盘哪些检测可以更早发现异常，不在生产主机上复现实验。

## 阶段五：安全地贡献

1. 先阅读 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)。
2. 新增 IOC 时保持 `hxxp(s)` 与 `[.]` 去武器化格式。
3. 新增测试时只生成合成 ID，禁止复制真实日志行。
4. PR 中说明数据来源、脱敏方式、验证命令和残余风险。

## 建议成果

- 一条有正反例和误报说明的防御规则；
- 一份基于脱敏夹具的时间线解析测试；
- 一份不包含私人数据的事件响应检查表；
- 一项对公开安全门禁的改进。
