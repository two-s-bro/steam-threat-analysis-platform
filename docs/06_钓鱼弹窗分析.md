# 钓鱼通知行为与检测线索

> 本页仅保留防御性行为摘要。原始 HTML、CSS、脚本、品牌资源、像素尺寸和可复刻布局不公开。

## 直接观察

私有事件证据显示，一组本地网页、样式和音频资源被用于在 Steam 客户端上下文中呈现仿冒通知。通知具有以下特征：

- 冒充官方支持场景并声称案件有新进展；
- 使用动态时间信息制造“刚刚发生”的感觉；
- 带有固定的伪造案件标识；
- 用户交互后进入被篡改的帮助路由；
- 路由携带账户相关标识并指向历史恶意基础设施。

这里描述的是观察到的社会工程行为，不提供通知结构、脚本逻辑或视觉复刻参数。

## 为什么容易误导用户

| 因素 | 防御性解释 |
|------|------------|
| 客户端内呈现 | 用户可能把应用内部窗口误认为可信来源 |
| 品牌一致性 | 字体、声音和视觉语言会降低警惕 |
| 时间与案件语境 | 新近、待处理的支持事件会制造紧迫感 |
| 路由劫持 | 看似正常的帮助入口可能被本地客户端文件改写 |

## 稳定检测信号

不要只依赖诱饵文字或单个资源名。优先组合：

1. Steam UI 资源在非官方更新窗口发生写入；
2. 本地通知资源与同批异常可执行文件同时落地；
3. 帮助/支持路由解析结果指向 `nexustechsolution[.]top`；
4. `steam.cfg` 同时出现禁用更新的异常配置；
5. 用户级 Run 键与上述文件写入在时间上相关。

## 调查与响应

- 记录窗口所属进程、父进程、文件签名、资源创建时间与 SHA-256；
- 从代理、DNS 或 EDR 历史中核验去武器化 IOC，不主动访问该主机；
- 从可信设备进入 Steam 官方支持站点核验是否真的存在支持案件；
- 规则未命中或窗口消失都不能证明终端安全；
- 处置步骤遵循 [`how-to-remove.md`](how-to-remove.md)，不要复制批量删除脚本。

## 误报边界

正常客户端也会呈现通知、播放音效并访问官方帮助页面。只有在文件完整性异常、路由目的地异常、持久化和落地组件等多个信号共同出现时，才能提高判断置信度。
