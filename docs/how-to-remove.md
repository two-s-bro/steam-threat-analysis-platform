# Steam 账号与终端事件响应检查表

> 这是一份防御性检查表，不是“一键清除”工具，也不能证明系统已经干净。若设备属于公司、学校或其他组织，请先联系其安全/IT 团队并遵守证据保全流程。

## 1. 先保护账号

在一台你有理由信任的设备上执行账号操作，避免继续从疑似受感染的主机输入凭据。

1. 按 [Steam 官方被盗账号流程](https://help.steampowered.com/en/wizard/HelpWithAccountStolen) 检查并恢复账号。
2. 保护与 Steam 绑定的邮箱：更换唯一密码，并按邮箱服务商指引启用多因素认证。
3. 为 Steam 使用独立密码，检查异常安全通知、登录和交易。
4. 启用并检查 [Steam Guard](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C) 中的授权设备。
5. 只通过 `steampowered.com`、`steamcommunity.com` 和 `help.steampowered.com` 等官方域名登录。

Steam 官方建议在重置 Steam 密码前先扫描计算机，并同时保护关联邮箱；本项目不替代官方支持。

## 2. 控制终端风险

- 如组织流程允许，暂时隔离疑似主机的网络连接；不要访问历史 C2。
- 不要运行、恢复、解包或上传可疑文件。
- 记录发现时间、告警名称、文件路径、SHA-256、父进程和持久化位置。
- 使用已更新的系统安全产品执行完整或离线扫描；企业设备应交由 EDR/事件响应团队处置。
- 高价值账号、支付信息或其他凭据曾在该主机使用时，扩大到相应账号的会话撤销和密码轮换。

## 3. 只读调查信号

以下信号来自单次事件，出现一个信号并不足以单独判定恶意；不出现也不能证明安全。

| 数据源 | 调查信号 |
|--------|----------|
| 用户级 Run 键 | `SteamHelper`、`SteamService`、`WindowsUpdateService` 指向异常目录或同批文件名 |
| 文件遥测 | `SteelDungeon.exe`、`NexusTechNotify.exe`、`locale_patch.dll` 等组合出现 |
| Steam 配置 | 非预期的 `BootStrapperInhibitAll=enable` 与 `BootStrapperForceSelfUpdate=disable` |
| 客户端完整性 | Steam UI 资源在非更新窗口发生变化 |
| 网络历史 | 与 `nexustechsolution[.]top` 或列出的端点相符的历史 DNS/代理记录 |

将发现与 [`../evidence/sample-hashes.json`](../evidence/sample-hashes.json) 对照时，只比较已有授权证据的哈希；不要为获取样本而下载文件。

## 4. 修复决策

不要复制网上的批量删目录、强杀进程或删注册表脚本。文件名可能冲突，路径也可能属于正常软件，未经核验的命令会造成误删和证据损失。

优先顺序应由受影响主机的所有者或安全团队决定：

1. 保全所需证据；
2. 由安全产品隔离已确认的文件和持久化项；
3. 修复或重新安装受篡改的软件；
4. 对高保证场景，从可信介质重装/恢复系统；
5. 安装更新并重新扫描后，才恢复正常网络和账号使用。

## 5. 完成后的验证

- 重启后复查安全产品告警与持久化遥测；
- 从可信设备确认邮箱和 Steam 的登录、授权设备、交易与安全设置；
- 对比 Steam 客户端文件完整性或重新安装官方客户端；
- 记录已处置项、未验证项和后续监控期限；
- 若异常复现或无法解释，停止自行处理并升级给专业事件响应人员。

“扫描未发现”或“规则未命中”都不是系统干净的证明。需要账号恢复时始终以 Steam 官方支持流程为准。
